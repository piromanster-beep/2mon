# Как контрибьютить в 2mon

Спасибо, что хотите помочь проекту. Ниже — коротко о процессе.

## Что приветствуется

- Исправление багов и опечаток — в коде и документации.
- Новые адаптеры вебхуков и готовые конфиги для систем мониторинга.
- Тесты: покрытие сейчас неполное (см. [DEVELOPMENT.md](DEVELOPMENT.md)).
- Улучшение текстов бота и админки.

## Перед началом

- Посмотрите [открытые issues](https://gitflic.ru/project/piroman99/2mon/issues).
- Для крупных изменений сначала создайте issue и опишите идею — так не придётся переделывать.

## Процесс

1. Форкните репозиторий (или создайте ветку, если у вас есть права).
2. Заведите ветку от `main`: `fix/...`, `feat/...`, `docs/...`.
3. Внесите изменения, добавьте или обновите тесты.
4. Прогоните локальные проверки:

   ```bash
   make check                     # gofmt + go vet + go test — то же, что гоняет CI
   go test -race -count=1 ./...   # с детектором гонок (нужен cgo/gcc)
   ```

5. Коммиты — осмысленные, в одном стиле с историей репозитория.
6. Откройте merge request в `main`. Опишите, что и зачем меняете и как проверяли.

## Требования к коду

- `gofmt`-чистота (обязательно: CI это проверяет).
- Публичные функции и неочевидные места — с комментариями.
- Узкие интерфейсы и передача зависимостей параметрами вместо глобалов.
- Не логируйте токены пользователей и тексты сообщений.
- Секреты — только через переменные окружения, никогда в коде.
- Новые переменные окружения добавляйте в `.env.example` и таблицу в [README.md](README.md).

## CI

`gitflic-ci.yaml` запускается на каждый push и merge request: `gofmt`, `go vet`,
`go test -race`; сборка — только на ветке `main`. Merge request не мержится,
если CI красный.
